## 📋 What is the Forward Return Tracker?

The Forward Return Tracker is a **background service** that automatically captures future price movements for every trading signal generated by your workers. This data is **critical** for optimizing Take Profit and Stop Loss levels based on real performance data.

### Why It's Important:

1. **Analyzes ALL Signals** - Not just executed trades, but also rejected signals
2. **Captures Real Price Movement** - Records actual prices at 5m, 15m, 60m, 240m after each signal
3. **Calculates MFE/MAE** - Max Favorable Excursion and Max Adverse Excursion
4. **Enables TP/SL Optimization** - Provides data to calculate optimal TP/SL via percentiles

### Example:

```
Signal Generated at 09:35:00
Symbol: AAPL @ $150.00
Worker: daily_plays

Forward Return Tracker automatically captures:
├─ 5m later (09:40:00): $151.20 → +0.80% return
├─ 15m later (09:50:00): $152.50 → +1.67% return
├─ 60m later (10:35:00): $153.80 → +2.53% return
└─ 240m later (13:35:00): $151.00 → +0.67% return

MFE (Max Favorable): +2.53%
MAE (Max Adverse): -0.20%
```

This data allows you to see that **75% of signals reach +2.53%**, so you could set TP accordingly.

## 🏗️ Architecture

### Components:

1. **ForwardReturnTracker** ([core/forward_return_tracker.py](../core/forward_return_tracker.py))
   - Background asyncio task
   - Monitors `signal_events` table for pending tracking
   - Schedules price captures at 4 intervals (5m, 15m, 60m, 240m)
   - Calculates MFE/MAE automatically
   - Updates database with results

2. **TradeEventLogger** ([core/trade_event_logger.py](../core/trade_event_logger.py))
   - Logs all signals (accepted + rejected)
   - Integrated into BaseWorkerLogic
   - Provides `update_forward_returns()` method

3. **Database Tables**:
   - `signal_events` - Stores all signals with forward tracking data
   - Extended via [database/schema_extensions.sql](../database/schema_extensions.sql)

## 📊 How It Works

### 1. Signal Detection

Every 60 seconds, the tracker queries:

```sql
SELECT *
FROM signal_events
WHERE forward_tracked_at IS NULL  -- Not yet tracked
  AND timestamp >= datetime('now', '-24 hours')  -- Last 24h
  AND timestamp <= datetime('now', '-5 minutes')  -- At least 5min old
```

### 2. Price Capture Strategies

The tracker uses **3 strategies** to get historical prices (in order):

**Strategy 1: MarketDataFetcher** (if available)
- Fetches bars around target timestamp
- Uses closest bar to target time

**Strategy 2: Database Query**
- Queries `trade_intraday_bars` table
- Matches timestamp within tolerance (±2 minutes)

**Strategy 3: Current Price** (if recent)
- If timestamp is < 5 minutes ago
- Uses current live price

### 3. MFE/MAE Calculation

```python
# Maximum price reached across all intervals
max_price = max([price_5m, price_15m, price_60m, price_240m])

# Minimum price reached
min_price = min([price_5m, price_15m, price_60m, price_240m])

# MFE (Max Favorable Excursion)
mfe_percent = ((max_price - entry_price) / entry_price) * 100

# MAE (Max Adverse Excursion)
mae_percent = ((min_price - entry_price) / entry_price) * 100
```

### 4. Database Update

Updates `signal_events` table:

```sql
UPDATE signal_events SET
    forward_return_5m = ?,
    forward_return_15m = ?,
    forward_return_60m = ?,
    forward_return_240m = ?,
    max_price_reached = ?,
    min_price_reached = ?,
    mfe_percent = ?,
    mae_percent = ?,
    forward_tracked_at = datetime('now')
WHERE signal_id = ?
```

## ⚠️ Important Notes

### Data Requirements:

- **Minimum Sample Size**: 20 signals per worker/confidence bucket
- **Recommended**: 50-100 signals for reliable statistics
- **Time Frame**: 2-4 weeks of paper trading

### Limitations:

1. **Price Availability**:
   - Tracker needs historical bars in database OR live market data
   - If neither available, forward returns will be NULL
   - This is EXPECTED in testing/offline environments

2. **Market Hours**:
   - Price capture works best during market hours
   - After-hours signals may have limited data

3. **Memory**:
   - Each signal creates an async task
   - Tasks are cleaned up after completion
   - No memory leaks expected

### Best Practices:

1. **Start Early**: Run tracker from day 1 of paper trading
2. **Monitor Logs**: Check for errors regularly
3. **Verify Data**: After 1 week, check that forward returns are being captured
4. **Run Continuously**: Don't stop/start frequently (causes gaps in data)

## 🐛 Troubleshooting

### Problem: No forward returns captured

**Symptoms:**
```sql
SELECT COUNT(*) FROM signal_events WHERE forward_tracked_at IS NOT NULL;
-- Returns: 0
```

**Solutions:**

1. **Check if signals are old enough** (must be > 5 minutes old):
   ```sql
   SELECT COUNT(*)
   FROM signal_events
   WHERE forward_tracked_at IS NULL
     AND timestamp <= datetime('now', '-5 minutes');
   ```

2. **Check if historical bars exist**:
   ```sql
   SELECT COUNT(*) FROM trade_intraday_bars;
   SELECT COUNT(*) FROM market_intraday_bars;
   ```

3. **Check tracker logs**:
   ```bash
   grep "Could not get price" forward_tracker.log
   ```

4. **Verify MarketDataFetcher is configured** (if using live data)

### Problem: Tracker keeps crashing

**Solutions:**

1. **Check database permissions**:
   ```bash
   ls -la trading_data.db
   ```

2. **Check Python version** (requires 3.8+):
   ```bash
   python --version
   ```

3. **Check dependencies**:
   ```bash
   pip list | grep -E "sqlite|asyncio"
   ```

4. **Run with debug logging**:
   ```bash
   python run_forward_tracker.py --log-level DEBUG
   ```

### Problem: High CPU usage

**Solutions:**

1. **Increase check interval**:
   ```bash
   python run_forward_tracker.py --interval 120  # Check every 2 minutes
   ```

2. **Limit tracking window**:
   - Edit `core/forward_return_tracker.py` line 122
   - Change `hours_back=24` to `hours_back=12`
